# Комплексный анализ кодовой базы бэкенд-приложения

## Задача

Проведи детальный анализ предоставленной бэкенд кодовой базы и создай **структурированный технический обзор проекта** для команды разработчиков. Цель: понять архитектуру, технологии, паттерны, инфраструктуру, безопасность и особенности реализации.

## Структура анализа

### 1. Обзор структуры проекта

**Проанализируй файловую структуру и предоставь:**

* Схематичное дерево директорий (до **4-го уровня** вложенности)
* Краткое описание назначения каждой ключевой директории (1–2 предложения)
* Принципы организации кода (layered/hexagonal/clean architecture, DDD, microservices/monolith/modular monolith)
* Где лежат конфиги (env, YAML/JSON/TOML), миграции БД, схемы, OpenAPI/Proto, скрипты деплоя

### 2. Технологический стек

**Определи и опиши:**

* Язык(и) программирования и версии (TypeScript/Node.js, Go, Java/Kotlin, Python, Rust, .NET и т. п.)
* Основной фреймворк/рантайм (Express/NestJS, FastAPI/Django, Spring Boot/Quarkus, Gin/Fiber, Actix/Axum и т. п.)
* Работа с БД: тип(ы) СУБД (PostgreSQL, MySQL, MongoDB, Redis, ClickHouse и др.), ORM/миграции (Prisma, TypeORM, Hibernate, Flyway, Liquibase, Sequelize, Alembic)
* Транспорт и контракты: REST (OpenAPI), gRPC (Proto), GraphQL (SDL/Code-First), WebSocket/Streaming
* Кэш/очереди/стримы: Redis/Memcached, RabbitMQ/Kafka/NATS/SQS, background jobs (BullMQ, Celery, Sidekiq и т. п.)
* Инструменты сборки и запуска (Gradle/Maven, pnpm/npm/yarn, Poetry/pip, Cargo, Makefile, Bazel)
* Тестирование (JUnit/Jest/Vitest/PyTest/Testcontainers, e2e/contract tests)
* Обсервабилити: логирование (Structured logs), метрики (Prometheus/OpenTelemetry), трассировка (OTel/Jaeger/Zipkin), алёртинг
* Безопасность: валидация, аутентификация/авторизация (JWT/OAuth2/OIDC), секрет-менеджмент
* Основные зависимости и их назначение (таблица «пакет → зачем нужен»)

### 3. Архитектурные паттерны

**Выяви и опиши с примерами кода:**

* Слойность: контроллеры/handlers → сервисы/домен → репозитории/адаптеры; границы модулей
* DDD-тактики: агрегаты, value objects, доменные события; где применяются
* Обработка запросов: middleware/filters/pipes, валидация схем (Zod/JOI/class-validator)
* Управление конфигурацией (12-Factor): env, профили окружений, feature flags
* Работа с БД: unit of work, транзакции, паттерны репозиториев, миграции
* Интеграции: HTTP/gRPC клиенты, ретраи, circuit breaker, timeouts, idempotency
* Асинхронность: очереди, scheduler/cron, outbox/inbox, saga/choreography/orchestration
* Обработка ошибок и **унифицированные** ответы (error envelope), стратегии retry/backoff
* Роутинг/маршрутизация сервисов (в монолите/шлюзе/API Gateway)
* Версионирование API и обратная совместимость

### 4. API и работа с данными

**Проанализируй:**

* Контракты API: наличие и актуальность OpenAPI/Proto/SDL; генерация клиентов/серверов
* Семантика REST (статусы, идемпотентность, пагинация, фильтрация, сортировка), GraphQL-паттерны (N+1, DataLoader), gRPC-потоки
* Модели данных/схемы: ER-диаграммы (если есть), связи, индексы, констрейнты
* Миграции и сиды; стратегии эволюции схемы (expand/contract)
* Кэширование: keys, TTL, инвалидация, cache-aside/write-through
* Консистентность: транзакции, уровень изоляции, eventual vs strong

### 5. Стили и качество кода

**Оцени:**

* Конфигурации линтеров и форматтеров (ESLint/Prettier, golangci-lint, ktlint/spotless, flake8/black, rustfmt/clippy)
* Соглашения по именованию, структуре модулей, кодстайлу; соблюдение SOLID/CQRS/DRY/KISS
* Качество типизации (TS/Go/Rust/Java), null-safety, явные контрактные типы
* Тесты: юнит/интеграционные/e2e/контрактные; использование Testcontainers/MockServer/WireMock
* Покрытие тестами ключевого функционала (оценка/метрики, если доступны)
* Документация: README/ADR, комментарии, диаграммы (C4/PlantUML), автогенерация API-доков

### 6. Безопасность и соответствие требованиям

**Проверь и опиши:**

* Аутентификация/авторизация (JWT/OAuth2/OIDC, роли/права, атрибутный доступ)
* Валидация входных данных и санитизация
* Защита: rate limiting, CORS, CSRF (если релевантно), сигнатуры, HSTS/TLS, headers
* Хранение секретов (Vault/SM/KMS), ротация ключей, доступ по принципу наименьших привилегий
* Логи аудита, PII/PHI, комплаенс (GDPR/HIPAA/PCI-DSS) — если применимо
* Зависимости: SCA/Dependabot/Snyk, политика обновлений

### 7. Наблюдаемость и эксплуатация

**Опиши:**

* Структурированное логирование, корреляция (trace/span/request id)
* Метрики (бизнес/технические), дешборды, SLO/SLI/SLA, алёрты
* Трассировка распределённых запросов (OTel)
* Feature flags/конфигурация в рантайме

### 8. Производительность и надёжность

**Выяви:**

* Горячие пути (critical path), профилирование, пул соединений, пулы воркеров
* Кэш/индексы, N+1, batch-загрузки, лимиты памяти/CPU, GC-тюнинг (если релевантно)
* Паттерны устойчивости: bulkhead, circuit breaker, timeouts, retries с jitter
* Стратегии деградации/фолбэков; idempotent-ключи

### 9. Инфраструктура и доставка

**Опиши:**

* Скрипты в `package.json`/`Makefile`/`Gradle`/и т. п. и их назначение
* Контейнеризация: Dockerfile (multi-stage), docker-compose, healthcheck, non-root user
* Оркестрация: Kubernetes/Helm, сервис-мэш, ingress/gateway, конфиги/секреты
* CI/CD: пайплайны (GitHub Actions/GitLab CI/Jenkins), сборка артефактов, линт/тесты, security-сканы, прогрессивные деплои (blue-green/canary)
* Управление окружениями (dev/stage/prod), флаги, миграции при деплое, откаты

### 10. Ключевые модули и примеры

**Выбери 3–5 наиболее важных модулей/сервисов и для каждого предоставь:**

* Назначение и роль в системе
* Пример использования/фрагмент кода (15–25 строк), показывающий ключевой паттерн (например, контроллер → сервис → репозиторий; обработчик события; gRPC handler)
* Основные публичные методы/API
* Зависимости и интеграции (БД, очереди, внешние сервисы)

### 11. Паттерны и best practices

**Выдели характерные для проекта:**

* Повторно используемые паттерны (порт/адаптер, CQRS, event-driven, outbox)
* Подходы к асинхронной обработке и транзакционной надёжности
* Версионирование и совместимость API
* Миграции схем и управление данными
* Локализация и i18n (если релевантно для сообщений/ошибок)

### 12. Риски и техдолг

**Оцени:**

* Хрупкие места (single point of failure, жёсткие связи, отсутствующие таймауты)
* Устаревшие зависимости/версии
* Пробелы в тестировании/безопасности/наблюдаемости
* Предложи план снижения рисков (коротко: quick wins → mid-term → long-term)

## Дополнительные требования

* Приводи **конкретные примеры кода (15–25 строк)**, иллюстрирующие архитектурные решения (контроллер/handler, сервис, репозиторий, транзакция, обработчик события/очереди, клиент внешнего API).
* Отмечай **сильные стороны** и **зоны роста**.
* Выделяй нестандартные/интересные решения (почему так сделано, чем лучше/хуже альтернатив).
* Укажи **уровень сложности проекта** (junior/middle/senior friendly) и аргументируй.
* В больших проектах фокусируйся на **критичных компонентах** (аутентификация, биллинг, интеграции, оркестрация задач и т. п.).

## Ограничения

* Максимальная длина анализа: **3000–4000 слов**.
* Примеры кода должны быть **читаемыми и содержательными**, без избыточных кусков.
* Если какая-то информация **недоступна**, прямо это укажи и предложи, как восполнить (e.g., запустить `make test`, посмотреть логи, сгенерировать OpenAPI, открыть Helm values).
