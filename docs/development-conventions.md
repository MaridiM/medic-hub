# Соглашения по разработке

Этот документ фиксирует все технические правила и соглашения, принятые в проекте Doctor Lab для обеспечения единообразия и качества кодовой базы.

---

## 1. Именование файлов

### 1.1. Выбранный стандарт

Для всего проекта принят единый стиль именования файлов: **`kebab-case`** (слова в нижнем регистре, разделенные дефисом).

- **Frontend компоненты:** `patient-card.tsx`, `calendar-view.tsx`
- **Backend (модули, сервисы, резолверы):** `auth.service.ts`, `patients.resolver.ts`
- **Файлы с утилитами, хуками, типами:** `use-auth-hook.ts`, `date-utils.ts`
- **Документация:** `development-conventions.md`, `adr-001-database-choice.md`

**Исключения:**
- **Страницы и Layouts (Frontend):** Следуем соглашениям Next.js App Router (`page.tsx`, `layout.tsx`).
- **Имена классов (внутри файлов):** Используем `PascalCase` (например, класс `AuthService` в файле `auth.service.ts`).

### 1.2. Рассмотренные варианты

- **`PascalCase` для компонентов:** Рассматривался вариант именования React-компонентов в `PascalCase` (`PatientCard.tsx`), что является популярной практикой. По итогу обсуждения был выбран `kebab-case` для унификации со всем остальным проектом.

---

## 2. Стиль кода

- **Форматирование:** Код автоматически форматируется с помощью **Prettier** при сохранении. Настройки хранятся в `.prettierrc`.
- **Линтинг:** Проверка качества кода осуществляется с помощью **ESLint**. Правила хранятся в `eslint.config.mjs`.

---

## 3. База данных (Prisma)

- **Схема:** Названия моделей в схеме Prisma (`schema.prisma`) пишутся в `PascalCase`.
- **Маппинг:**
    - Все названия таблиц в базе данных должны быть в `snake_case` и во множественном числе. Это достигается с помощью `@@map("users")`.
    - Все названия полей/колонок в базе данных должны быть в `snake_case`. Это достигается с помощью `@map("created_at")`.

---

## 4. Структура Модулей и Стиль Экспорта

### 4.1. Публичный реэкспорт (Barrel Exports)

Для создания публичного API модулей и компонентов следует использовать `index.ts` файлы. Это упрощает импорты и скрывает внутреннюю структуру модуля.

**Разрешенные синтаксисы:**
```typescript
// Полный реэкспорт
export * from './my-component';

// Именованный реэкспорт
export { MyButton } from './my-button';

// Реэкспорт дефолтного экспорта с новым именем
export { default as MySpecialInput } from './my-special-input';
```

### 4.2. Соглашения для Frontend

- **Стиль компонентов и страниц:** Все React-компоненты и страницы должны быть объявлены как **стрелочные функции** (`const MyComponent = () => { ... };`).

- **Стиль экспорта:**
    - **Страницы** (в директории `app`): Должны использовать **`export default`**. Это требование Next.js App Router.
    ```typescript
    const HomePage = () => {
      return <div>Home</div>;
    };
    export default HomePage;
    ```
    - **Компоненты и утилиты:** Должны использовать **именованный `export`**. Это позволяет четко разграничить переиспользуемые части кода от страниц.
    ```typescript
    export const PatientCard = () => {
      return <div>Patient Card</div>;
    };
    ```
